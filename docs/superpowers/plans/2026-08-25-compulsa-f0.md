# Compulsa F0 — Núcleo de cómputo · Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar la F0 del PRD (`doc/PRD.md` §14): workspace funcional donde se crea una obra, se sube documentación PDF, un pipeline la analiza (láminas → rótulos → entidades con provenance), se genera el cómputo por rubros en planilla editable con link bidireccional al visor, los huecos van a una bandeja de consultas con acciones de un click, y todo se exporta a XLSX — testeado, con golden set de regresión.

**Architecture:** Next.js 15 App Router con dominio puro separado (`src/lib/computo|rubros|hallazgos`, sin I/O), fronteras por interfaz para IA (`AnalysisProvider` mock/Claude) y storage (fs local/Supabase futuro), y Drizzle sobre PGlite (dev/test) o Postgres (`DATABASE_URL`). El pipeline de análisis es un conjunto de funciones idempotentes con estados persistidos por lámina. La UI acopla planilla↔visor por query param, no por imports.

**Tech Stack:** Next.js 15 · React 19 · TypeScript strict · Tailwind CSS v4 · Drizzle ORM + drizzle-kit · @electric-sql/pglite · pdf-lib · pdfjs-dist · exceljs · zod · @anthropic-ai/sdk (solo en `analysis/claude.ts`) · Vitest.

- **Dependencias congeladas tras la Tarea 1.** Ninguna tarea posterior toca `package.json`; si te falta una dependencia, reportá BLOCKED — no la instales.

- **P4:** el sistema jamás inventa un dato: lo no explícito genera hallazgo. Confianza < 0.7 ⇒ degrada a consulta.
- **TDD:** test que falla → implementación mínima → test verde → commit. Asserts con números exactos.
- **Los tests jamás usan red ni `ANTHROPIC_API_KEY`** — provider mock siempre.

## Contratos compartidos (fuente de verdad: `src/types/domain.ts`, Tarea 2)

Todas las tareas usan EXACTAMENTE estos nombres y tipos:

```ts
export type BBox = [number, number, number, number]; // [x, y, ancho, alto] normalizados 0–1, origen arriba-izquierda
export interface Fuente { laminaId: string; bbox: BBox; detalle?: string }
export type Origen = 'explicito' | 'deducido' | 'supuesto';
export type EstadoReforma = 'existente' | 'demoler' | 'nueva' | 'na';
export type TipoObra = 'nueva' | 'reforma' | 'ampliacion';
export type RubroId = 'aberturas' | 'seco' | 'pintura' | 'gruesa';
export type Unidad = 'u' | 'm' | 'ml' | 'm2' | 'm3' | 'l' | 'kg';
export type TipoEntidad = 'ambiente' | 'muro' | 'tabique' | 'abertura' | 'artefacto' | 'terminacion' | 'otro';
export type Disciplina = 'arquitectura' | 'estructura' | 'instalaciones' | 'otra';
export type TipoLamina = 'planta' | 'corte' | 'vista' | 'detalle' | 'planilla' | 'otra';
export type EstadoAnalisis = 'pendiente' | 'procesando' | 'analizada' | 'bloqueada_escala' | 'error';
export type TipoHallazgo = 'faltante' | 'inconsistencia' | 'existente_confirmar' | 'supuesto';
export type EstadoHallazgo = 'abierto' | 'respondido' | 'descartado';
export type EstadoRubro = 'borrador' | 'revision' | 'aprobado';

export interface EntidadDetectada {
  tipo: TipoEntidad;
  nombre: string;                       // "Dormitorio 1", "V2", "Tabique T1"
  bbox: BBox;
  confianza: number;                    // 0–1
  estadoReforma: EstadoReforma;         // 'na' en obra nueva
  atributos: Record<string, number | string | boolean | null>;
}
// Atributos convencionales por tipo (claves exactas):
//   ambiente:  superficieM2, perimetroM, alturaM?, vanosM2?
//   abertura:  tag, tipologia ('ventana'|'puerta'|'paño fijo'), anchoM?, altoM?, material?, vidrio?
//   tabique:   largoM, alturaM?, caras? (default 2), tipo ('durlock')
//   muro:      largoM, alturaM?, espesorM?, tipo ('mamposteria')
//   terminacion: superficieM2, ubicacion ('piso'|'cielorraso'|'pared'), ambiente (nombre), material?

export interface RotuloDetectado {
  titulo: string | null; codigo: string | null;
  disciplina: Disciplina | null; tipoLamina: TipoLamina | null;
  escala: string | null;            // "1:100"
  escalaConfiable: boolean;
  revision: string | null; confianza: number;
}

export interface LaminaInput {
  laminaId: string;
  pdfBytes: Uint8Array;             // PDF de UNA página
  documentoNombre: string;          // nombre del archivo original subido
  numeroPagina: number;             // 1-based dentro del original
  textoExtraido?: string;
}
export interface ObraContexto { obraId: string; tipoObra: TipoObra }

export interface ItemComputo {
  rubro: RubroId; descripcion: string; unidad: Unidad;
  cantNeta: number; desperdicioPct: number; cantCompra: number;
  presentacion: string; origen: Origen; fuentes: Fuente[];
  confianza: number; entidadRef?: string;
  claveItem: string;                // estable para diff/golden, ej. "seco.placas", "aberturas.V2"
}
export interface HallazgoDetectado {
  tipo: TipoHallazgo; rubro: RubroId | null; descripcion: string;
  clave: string;                    // única por obra para idempotencia, ej. "seco.altura_tabiques.T1"
  checklistItem?: string; bloqueante: boolean; fuentes: Fuente[];
  targetRef?: { entidadId: string; campo: string };  // si responderlo actualiza una entidad
}
```

`src/types/domain.ts` también exporta los schemas Zod correspondientes (`zEntidadDetectada`, `zRotuloDetectado`) usados por providers y API.

### Tarea 3: Motor de cómputo, rubros y taxonomía de hallazgos

**Files:** Create: `src/lib/computo/{unidades.ts,presentacion.ts,engine.ts,sanity.ts}`, `src/lib/rubros/{index.ts,aberturas.ts,seco.ts,pintura.ts,gruesa.ts}`, `src/lib/hallazgos/{taxonomia.ts,gate.ts}`, `tests/unit/{presentacion.test.ts,rubro-aberturas.test.ts,rubro-seco.test.ts,rubro-pintura.test.ts,rubro-gruesa.test.ts,sanity.test.ts,gate.test.ts}`.

**Interfaces — Consumes:** tipos de `@/types/domain`. **Produces:**
- `computarObra(entidades: EntidadPersistida[], tipoObra: TipoObra, rubros?: RubroId[]): { items: ItemComputo[]; hallazgos: HallazgoDetectado[] }` (en `engine.ts`; `EntidadPersistida = EntidadDetectada & { id: string; laminaId: string }`). Corre cada plantilla + sanity checks.
- `PlantillaRubro { id, nombre, desperdicioDefaultPct, computar(entidades, tipoObra): { items, hallazgos } }`; `PLANTILLAS: Record<RubroId, PlantillaRubro>` en `rubros/index.ts`.
- `ceilAPresentacion(cantidad: number, contenido: number): { unidades: number; cantCompra: number }` — `unidades = Math.ceil(cantidad/contenido)`, `cantCompra = round2(unidades*contenido)`.
- `latasParaLitros(litros: number): { latas: Record<number, number>; litrosTotales: number }` — greedy sobre [20,10,4,1]; el remanente sube a la lata más chica que lo cubra.
- `puedeAprobarRubro(rubro: RubroId, hallazgos: {rubro, bloqueante, estado}[]): { ok: boolean; bloqueantes: number }` — false si existe hallazgo del rubro `abierto && bloqueante` (RF-404).
- `redondear2(n)`, `redondearEntero(n)` en `unidades.ts`.

**Reglas de cómputo por rubro (números exactos = datos de la plantilla):**
- *aberturas:* agrupa entidades `abertura` (estadoReforma `nueva`|`na`) por `tag`; ítem unidad `u`, `claveItem: "aberturas.<tag>"`, desperdicio 0. Sin `anchoM` o `altoM` → hallazgo `faltante` bloqueante `clave: "aberturas.medidas_vano.<tag>"`, `targetRef {entidadId, campo: 'anchoM'|'altoM'}`. Reforma: `demoler` → ítem "Retiro de <tag>" `claveItem "aberturas.retiro.<tag>"`; `existente` → no computa.
- *seco:* tabiques durlock nuevos: m² = `largoM × alturaM × caras(=2)`. Sin `alturaM` → hallazgo bloqueante `"seco.altura_tabiques.<nombre>"` con targetRef campo `alturaM`, y el tabique NO se computa. Ítems (claveItem fijo, cantidades sumadas sobre todos los tabiques computables): `seco.placas` (m², desperdicio 12%, placa 2,88 m²), `seco.soleras` (ml = 2×Σlargo, barra 2,60 m), `seco.montantes` (u = Σ(ceil(largo/0,40)+1), presentación "tira 2,60 m", desperdicio 0), `seco.tornillos` (u = 15×m² netos, caja 500), `seco.masilla` (kg = 0,9×m², balde 15 kg), `seco.cinta` (ml = 2,3×m², rollo 90 m).
- *pintura:* por ambiente: paredes m² = `perimetroM × alturaM − (vanosM2 ?? 0)`; sin `alturaM` → hallazgo bloqueante `"pintura.altura_ambiente.<nombre>"`; sin `vanosM2` → hallazgo `supuesto` NO bloqueante `"pintura.vanos_sin_descontar.<nombre>"` ("se computó sin descontar vanos") y se computa bruto. Cielorraso m² = superficieM2. Látex interior: 2 manos, rendimiento 10 m²/L por mano, desperdicio 5% → litros → `latasParaLitros`. Ítems `pintura.latex_paredes`, `pintura.latex_cielorrasos` (presentación = detalle de latas, ej. "1 lata 20 L + 1 lata 4 L").
- *gruesa:* muros mampostería nuevos: m² = largo×alto (sin altura → bloqueante `"gruesa.altura_muros.<nombre>"`). Ladrillo hueco 12: 16,5 u/m² desp. 5% → pallet 198 u (`gruesa.ladrillos`); cemento 8 kg/m² → bolsa 50 kg (`gruesa.cemento`); cal 12 kg/m² → bolsa 25 kg (`gruesa.cal`); arena 0,04 m³/m² → redondeo a 0,5 m³ (`gruesa.arena`). `demoler` → `gruesa.demolicion` m² sin desperdicio, presentación "global".
- *sanity.ts:* por ambiente con terminaciones piso y cielorraso: si `|piso − cielo| / piso > 0,10` → hallazgo `inconsistencia` no bloqueante `clave "sanity.piso_cielo.<ambiente>"` citando ambas fuentes.
- Ítems heredan `fuentes` de sus entidades (concatenadas, sin duplicar laminaId+bbox idénticos) y `confianza` = mínima de las entidades usadas. Confianza < 0,7 ⇒ el ítem NO se emite y sale hallazgo `faltante` bloqueante `"<rubro>.baja_confianza.<clave>"` (regla de oro §11.b).

**Tests con números pinneados (escribilos ANTES de cada plantilla):** tabique 5×2,6 m 2 caras → 26 m²; placas: 26×1,12=29,12 → **11 placas / 31,68 m²**; soleras 10 ml → **4 barras**; montantes ceil(5/0,4)+1=**14**; tornillos 390 → **1 caja (500 u)**; masilla 23,4 kg → **2 baldes (30 kg)**; cinta 59,8 ml → **1 rollo**. Pintura: ambiente 4×3 m (per. 14, alto 2,6, vanos 3,5) → paredes 32,9 m²; +cielo 12 m²; litros paredes = 32,9×2/10×1,05=6,909 → latas **{4:1, 1:3}? NO — greedy: 6,909 → resto tras 0×20, 0×10 → 1×4=4, resto 2,909 → 3×1** ⇒ `{4:1, 1:3}`, 7 L total. Gruesa: muro 6×2,6=15,6 m²; ladrillos 15,6×16,5×1,05=270,27 → **2 pallets (396 u)**; cemento 124,8 kg → **3 bolsas**; cal 187,2 → **8 bolsas**; arena 0,624 → **1,0 m³**. Aberturas: 2×"V2" con medidas → 1 ítem cantNeta **2**; "P1" sin altoM → hallazgo bloqueante con targetRef. Reforma: tabique `existente` no computa; muro `demoler` 3×2,6 → demolición **7,8 m²**. Gate: 1 bloqueante abierto → `ok:false`; respondido → `ok:true`.
